# Codebase Structure

## Directory Layout

```
[project-root]/
├── .github/
│   ├── ISSUE_TEMPLATE/    # Bug report, feature request, config
│   ├── PULL_REQUEST_TEMPLATE.md
│   └── workflows/
│       └── ci.yml         # CI: install, build, test, artifact drift check
├── docs/                  # GitHub Pages live demo + brand assets
│   ├── index.html         # Live demo page (Try the tool)
│   ├── favicon.svg
│   ├── social-preview.html / social-preview.png
│   ├── highlight-tool.min.js   # Build artifact copy served by the demo
│   └── screenshots/       # README screenshots
├── test/
│   └── core.test.js       # node:test unit suite (stubs a browser)
├── highlight-tool.js      # Source — the entire tool, one IIFE
├── highlight-tool.min.js  # Build artifact (terser)
├── bookmarklet.txt        # Build artifact (javascript: + minified)
├── package.json           # Build script, test script, metadata
├── package-lock.json
├── README.md
├── CHANGELOG.md
├── CONTRIBUTING.md
├── SECURITY.md
├── CODE_OF_CONDUCT.md
├── LICENSE
└── .editorconfig / .gitignore / .gitattributes
```

## Directory Purposes

**`.github/`:**
- Purpose: GitHub automation and contribution templates
- Contains: Issue templates (`bug_report.md`, `feature_request.md`, `config.yml`), `PULL_REQUEST_TEMPLATE.md`, the CI workflow
- Key files: `.github/workflows/ci.yml` — runs `npm ci`, `npm run build`, `npm test`, then fails if `git diff` shows drift in `highlight-tool.min.js`, `bookmarklet.txt` or `docs/highlight-tool.min.js`

**`docs/`:**
- Purpose: The GitHub Pages live demo plus brand assets referenced by the README
- Contains: `index.html` (demo page whose "Try the tool" button injects `highlight-tool.min.js`), `favicon.svg`, `social-preview.html`/`.png`, the build-artifact copy `highlight-tool.min.js`, and `screenshots/` (README images)
- Key files: `docs/index.html`, `docs/highlight-tool.min.js` (regenerated by `npm run build`)
- Note: `docs/IMPROVEMENTS.md` exists on disk but is a private working document — excluded from git, never commit it

**`test/`:**
- Purpose: Unit tests for the pure functions and highlight operations
- Contains: One file, `core.test.js`, using `node:test` + `node:assert/strict`
- Key files: `test/core.test.js` — stubs `window`/`document`/`alert` so the source IIFE loads in Node, then `eval`s `highlight-tool.js` and asserts against `window._HL` and `window._HL.__test`

**`reports/` and `.cortexkit/`:**
- Purpose: Local tooling only - commit-validation reports and magic-context state
- Contains: Timestamped `commit-validate_*.md` reports; `.cortexkit/` holds local tool metadata
- Note: All three are gitignored (`reports/`, `.cortexkit/`, `.playwright-mcp/` in `.gitignore`); not part of the shipped project

## Key File Locations

**Source:** `highlight-tool.js`: the entire tool in one IIFE — state, popup UI, picking, overlay rendering, coordinate conversion, capture, download, and the `window._HL` facade. Edit only this file; run `npm run build` afterwards.

**Entry points:** `bookmarklet.txt`: the installable bookmarklet URL (starts with `javascript:`), generated by `npm run build` from `highlight-tool.min.js`. The demo page entry is `docs/index.html`.

**Configuration:** `package.json`: `build` script (terser + version check + artifact copies), `test` script (`node --test test/core.test.js`), `engines: node >=18`. CI configuration is `.github/workflows/ci.yml`. Editor defaults are `.editorconfig`.

**Core logic:** `highlight-tool.js`: layers in source order — closure `state`, `openPopup()` + `wirePopupControls()`, delegated list handlers (`onHlListClick`/`onHlListChange`), wheel fine-tuning (`onPopupWheel`), icons, `syncScMode()`/`renderPopup()`, highlight ops (`updateHL`/`removeHL`/`moveHL`/`renumberBadges`), picking (`enablePick`/`disablePick`), `clearAll()`/`cleanup()`, coordinate conversion, `renderHighlights()` + style helpers, capture (`takeScreenshot`/`doCapture`/`cropToHighlights`), download, then the `window._HL` export.

**Tests:** `test/core.test.js`: run with `npm test`.

**Build artifacts:** `highlight-tool.min.js`, `bookmarklet.txt`, `docs/highlight-tool.min.js` — all generated by `npm run build` from `highlight-tool.js`; never hand-edit, and CI verifies they are in sync.

## Naming Conventions

**Files:** kebab-case for repo/metadata files (`highlight-tool.js`, `package-lock.json`, `bookmarklet.txt`); `social-preview.*` and `screenshot-*` for docs assets.

**Code:** `camelCase` functions and variables (`openPopup`, `renderHighlights`, `captureDirty`). Function names read as verbs for actions (`takeScreenshot`, `clearAll`) and nouns for factories/accessors (`getDefaultHighlight`, `getHighlights`).

**DOM classes:** `hl-` prefix for everything the tool injects into the host page: `hl-overlay` (highlight box), `hl-picker-overlay`, `hl-hover-overlay` (picking overlays). Pick a class the host page could never collide with.

**DOM attributes:** `data-hl` (action: `update`/`move`/`remove`), `data-id`, `data-sec` (section), `data-key`, `data-sub` (nested key), `data-dir`, `data-int` for popup controls; `data-hl-id` on injected overlays.

**Namespace:** `window._HL` — single global; the IIFE deletes it on `cleanup()` and overwrites it on re-activation.

## Where to Add New Code

This is a deliberately single-file project. Keep it that way: add new logic in `highlight-tool.js` next to the layer it belongs to, not in a new file.

**New pure helper (e.g. a CSS/format utility):** add the function inside the IIFE near its peers, expose it on `window._HL.__test`, and add `node:test` cases in `test/core.test.js` following the existing stubbed-browser pattern.

**New highlight field or editor control:** extend the default shape in `getDefaultHighlight()`; render the input in `renderPopup()` with the `data-hl="update" data-sec="..." data-key="..."` protocol; apply it in `renderHighlights()`; update the shape assertions in `test/core.test.js`.

**New capture mode:** branch inside `doCapture()` alongside `viewport`/`fullpage`/`highlights`; add the radio option in `openPopup()` and keep `syncScMode()`'s guard logic for modes that need highlights to exist.

**New public API surface:** add the method to `window._HL` in the facade at the bottom of `highlight-tool.js`.

**After any source change:** run `npm run build` to regenerate `highlight-tool.min.js`, `bookmarklet.txt` and `docs/highlight-tool.min.js`, and `npm test` — CI fails on artifact drift, so commit the regenerated artifacts together with the source change.
